## 一、环境准备

### 1.1 基础软件要求

| 软件 | 版本要求 | 说明 |
|------|----------|------|
| Go | 1.22+ | 后端编译运行 |
| MySQL | 8.0+ | 数据库 |
| Memurai / Redis | 兼容 Redis 6+ | 缓存，端口 6379 |
| protoc | 25.1+ | Protobuf 编译器 |
| protoc-gen-go | v1.36+ | Go 代码生成插件，需放入 `$GOPATH/bin` |
| Node.js | v20+ | 前端构建 |
| Cocos Creator | 3.8.8 | 前端引擎 |

### 1.2 确认环境可用

```bash
# 检查 Go
go version    # 期望: go1.22.x

# 检查 MySQL
mysql --version   # 期望: 8.0+

# 检查 protoc
protoc --version  # 期望: libprotoc 25.1+

# 检查 protoc-gen-go（需在 GOPATH/bin 下）
ls $GOPATH/bin/protoc-gen-go    # Windows: dir %GOPATH%\bin\protoc-gen-go.exe

# 检查 Node.js
node --version  # 期望: v20+

# 检查 Redis/Memurai（端口 6379 是否监听）
# Windows PowerShell:
Test-NetConnection -ComputerName 127.0.0.1 -Port 6379
```

### 1.3 启动依赖服务

```bash
# 启动 MySQL（Windows）
"C:\Program Files\MySQL\MySQL Server 8.4\bin\mysqld.exe" --defaults-file="C:\Program Files\MySQL\MySQL Server 8.4\my.ini" --console

# 启动 Memurai/Redis（如果未自动启动）
# Memurai 通常开机自启，确认端口 6379 已监听即可
```

### 1.4 项目 Go 依赖安装

```bash
cd backend
```

## 二、数据库层

### 2.1 创建人物系统表

**文件：** `sql/character_system.sql`  
**操作：** 在 `game_main` 库中创建 10 张新表

```bash
# 执行建表 SQL
mysql -u root -p < sql/character_system.sql
```

**10 张表说明：**

| # | 表名 | 用途 | 对应技术方案 |
|---|------|------|-------------|
| 1 | `character_base` | 角色基础信息（名称/性别/种族/形态） | Table 4 |
| 2 | `character_attributes` | 五维属性 + 气血/灵力/魂力衍生值 | Table 5 |
| 3 | `character_qi_elements` | 五行修炼独立记录（金木水火土各一行） | Table 6 |
| 4 | `character_realm` | 境界/经验/心魔/因果/道行 | Table 7 |
| 5 | `character_death_state` | 死亡/鬼修/夺舍次数/公敌标记 | Table 8 |
| 6 | `reincarnation_log` | 六道轮回历史记录 | Table 9 |
| 7 | `heritage_ruins` | 遗迹洞府（死亡后财产存放） | Table 10 |
| 8 | `possess_log` | 夺舍历史记录 | Table 11 |
| 9 | `character_beast_state` | 兽身状态（种类/进化/化形） | Table 12 |
| 10 | `public_enemy_state` | 公敌状态（悬赏/天雷次数） | Table 13 |

### 2.2 验证建表结果

```sql
USE game_main;
SHOW TABLES LIKE 'character%';      -- 应显示 6 张表
SHOW TABLES LIKE 'reincarnation%';   -- 应显示 1 张表
SHOW TABLES LIKE 'heritage%';        -- 应显示 1 张表
SHOW TABLES LIKE 'possess%';         -- 应显示 1 张表
SHOW TABLES LIKE 'public_enemy%';    -- 应显示 1 张表
```

### 2.3 同步 schema.sql

**文件：** `sql/schema.sql`  
**操作：** 将 `character_system.sql` 中的 10 张表 DDL 追加到主建表脚本的 `player_attrs` 表之后、`game_session` 段之前。

> 如果已执行过步骤 2.1，此步骤仅更新 schema.sql 文件保持同步。

## 三、后端 Character Service（角色服务）

### 3.1 创建配置文件

**新建文件：** `backend/configs/character.yaml`

```yaml
server:
  port: 8005
  name: character-service

mysql:
  dsn: "root:password@tcp(127.0.0.1:3306)/game_main?charset=utf8mb4&parseTime=true"
  max_open_conns: 50
  max_idle_conns: 10

redis:
  addr: "127.0.0.1:6379"
  password: ""
  db: 0

jwt:
  secret: "xunxian-jwt-secret-key-change-in-prod"
  access_expires: 2
  refresh_expires: 7
```

> **注意：** `mysql.dsn` 中的密码需与你本地 MySQL root 密码一致。

### 3.2 创建核心业务逻辑

**新建文件：** `backend/internal/character/service.go`

**包含内容（约 808 行）：**

#### 核心算法实现

| 算法 | 说明 | 实现位置 |
|------|------|----------|
| 多修经验倍率 | 单×1, 双×2, 三×3, 四×4, 五×9 | `GetExpMultiplier()` |
| 多修伤害倍率 | 单×1, 双×3, 三×6, 四×10, 五×15 | `GetDamageMultiplier()` |
| 境界经验递增 | 人一阶100, 二阶×1.5, ..., 九阶×5.0 | `GetRealmExpReq()` |
| 属性衍生引擎 | 精→气血/体魄/身法/根骨, 气→灵力/功法威力, 神→神识/精神壁垒 | `CalcDerivedAttrs()` |
| 角色名校验 | 2-8汉字 + 敏感词过滤 + 重名检测 | `validateName()` |

#### HTTP 接口

| 路由 | 方法 | Handler | 功能 |
|------|------|---------|------|
| `/character/create` | POST | `HandleCreate` | 创建角色（事务：同时插入4张表） |
| `/character/info` | GET | `HandleInfo` | 获取角色完整信息 |
| `/character/attributes` | GET | `HandleAttributes` | 获取五维属性及衍生值 |
| `/character/exp/add` | POST | `HandleExpAdd` | 增加经验（自动判断升阶） |
| `/character/realm/upgrade` | POST | `HandleRealmUpgrade` | 境界升级 |
| `/character/realm/breakthrough` | POST | `HandleBreakthrough` | 境界突破（含心魔劫/天劫） |
| `/character/qi/cultivate` | POST | `HandleQiCultivate` | 修炼五行属性 |
| `/character/qi/elements` | GET | `HandleQiElements` | 查询已修属性 |

#### 请求/响应字段说明

**创建角色 POST /character/create：**
```json
// 请求（需 Header: X-Account-ID）
{ "name": "李逍遥", "gender": 1 }

// 响应
{ "code": 0, "msg": "创建成功", "data": { "character_id": 1 } }
```

**增加经验 POST /character/exp/add：**
```json
// 请求
{ "character_id": 1, "exp_jing": 200, "exp_qi": 200, "exp_shen": 100 }

// 响应
{ "code": 0, "data": { "exp_jing": 200, "exp_qi": 200, "exp_shen": 100, "exp_req": 100, "multiplier": 1, "can_upgrade": true } }
```

**修炼五行 POST /character/qi/cultivate：**
```json
// 请求（element_type: 1=金 2=木 3=水 4=火 5=土）
{ "character_id": 1, "element_type": 1 }

// 响应
{ "code": 0, "msg": "开始修炼 金 属性", "data": { "element_type": 1, "element_name": "金", "element_count": 1, "exp_multiplier": 1 } }
```

### 3.3 创建服务入口

**新建文件：** `backend/cmd/character-service/main.go`

**功能：**
- 加载 `configs/character.yaml` 配置
- 连接 MySQL + Redis
- 注册 8 个 HTTP 路由
- 启动 HTTP 服务监听端口 8005
- 优雅关闭（SIGINT/SIGTERM）


```yaml
redis:

  password: ""
  db: 0

jwt:
  secret: "xunxian-jwt-secret-key-change-in-prod"
  access_expires: 2
  refresh_expires: 7
```

### 4.2 创建核心业务逻辑

**新建文件：** `backend/internal/death/service.go`

**包含内容（约 744 行）：**

#### 核心算法实现

| 算法 | 说明 | 实现位置 |
|------|------|----------|
| 夺舍成功率 | `possessorShen/targetShen × (1-0.15×(境界差-1))`，上限95%下限5% | `CalcPossessSuccessRate()` |
| 六道轮回分配 | 根据因果值加权随机 → 天/阿修罗/人/畜生/饿鬼/地狱 | `calcReincarnationType()` |
| 兽身精属性加成 | 兽形×1.5, 人形×1.0 | 在 `HandleBeastTransform` 中 |
| 三次夺舍强制变兽 | `possessCount >= 3` 时触发 | 在 `HandlePossessResult` 中 |

#### HTTP 接口

| 路由 | 方法 | Handler | 功能 |
|------|------|---------|------|
| `/death/trigger` | POST | `HandleTrigger` | 触发死亡 |
| `/death/reincarnation` | POST | `HandleReincarnation` | 六道轮回 |
| `/death/ghost/enter` | POST | `HandleGhostEnter` | 进入鬼修 |
| `/death/ghost/exit` | POST | `HandleGhostExit` | 鬼修重聚肉身 |
| `/death/possess/start` | POST | `HandlePossessStart` | 发起夺舍 |
| `/death/possess/result` | POST | `HandlePossessResult` | 夺舍结算 |
| `/death/beast/transform` | POST | `HandleBeastTransform` | 兽身化形切换 |
| `/death/ruins/create` | POST | `HandleRuinsCreate` | 创建遗迹洞府 |
| `/death/ruins/inherit` | POST | `HandleRuinsInherit` | 继承遗迹财产 |
| `/death/public-enemy/status` | GET | `HandlePublicEnemyStatus` | 查询公敌状态 |

#### 请求/响应字段说明

**触发死亡 POST /death/trigger：**
```json
// 请求
{ "character_id": 1, "death_type": 1, "is_dungeon": false }

// 响应
{ "code": 0, "msg": "死亡触发成功，可选择六道轮回或鬼修", "data": { "death_type": 1, "options": ["reincarnation", "ghost_cultivation"] } }
```

**六道轮回 POST /death/reincarnation：**
```json
// 请求
{ "character_id": 1 }

// 响应（示例）
{ "code": 0, "msg": "人道轮回：保留全部属性", "data": { "reincarnation_type": 3, "reincarnation_name": "人道", "new_attrs": {...}, "is_beast": false } }
```

**夺舍 POST /death/possess/start：**
```json
// 请求
{ "character_id": 1, "target_type": 1, "target_id": 100, "target_name": "路人甲" }

// 响应
{ "code": 0, "data": { "success_rate": 0.65, "success": true } }
```

### 8.2 联调测试流程

**测试完整链路：创建 → 属性 → 经验 → 修炼 → 死亡 → 轮回 → 公敌**

#### 步骤 1：创建角色

```bash
curl -X POST http://127.0.0.1:8005/character/create \
  -H "Content-Type: application/json" \
  -H "X-Account-ID: 1" \
  -d '{"name":"测试角色","gender":1}'
```

**期望返回：**
```json
{"code":0,"msg":"创建成功","data":{"character_id":1}}
```

#### 步骤 2：获取角色信息

```bash
curl http://127.0.0.1:8005/character/info?character_id=1
```

**期望返回：** 包含 base（名称/性别/种族）、derived（衍生属性）、realm（境界）

#### 步骤 3：获取五维属性

## 十、常见问题排查

### Q1: 创建角色返回 `{"code":401,"msg":"未认证"}`

**原因：** 请求未携带 `X-Account-ID` 请求头  
**解决：** 添加 `-H "X-Account-ID: 1"` 到请求头

### Q2: 创建角色返回 `{"code":400,"msg":"名称含非法字符"}`

**原因：** 请求体编码问题（PowerShell 中文编码）  
**解决：** 使用 Go 测试脚本或确保 JSON body 以 UTF-8 编码发送

### Q3: 修炼五行返回 `{"code":400,"msg":"五行类型只能为1-5"}`

**原因：** 请求字段名错误，应使用 `element_type` 而非 `element`  
**解决：** 请求体改为 `{"character_id":1,"element_type":1}`

### Q4: 增加经验返回 `exp_jing:0, exp_qi:0, exp_shen:0`

**原因：** 请求字段名错误，应分别传 `exp_jing/exp_qi/exp_shen` 而非 `exp`  
**解决：** 请求体改为 `{"character_id":1,"exp_jing":200,"exp_qi":200,"exp_shen":100}`

### Q5: `go build` 报 `syntax error: non-declaration statement outside function body`

**原因：** Go 文件头部出现重复 `package` 声明  
**解决：** 确保文件第 1 行（或注释后）只有一个 `package xxx` 声明

### Q6: 前端 TS 编译报 `类型"TokenManager"上不存在属性"getPlayerId"`

**原因：** UI 代码误用了 TokenManager 获取角色 ID  
**解决：** 改用 `PlayerManager.playerId`：
```typescript
import { PlayerManager } from '../manager/PlayerManager';
private _playerManager: PlayerManager = new PlayerManager();
this._characterId = this._playerManager.playerId;
```

### Q7: 前端 TS 编译报 `模块"cc"没有导出的成员"ProgressBar"`

**原因：** Cocos Creator 3.8.8 的 ProgressBar 未从 cc 模块导出  
**解决：** 使用 Node 类型 + 强制转换：
```typescript
@property(Node) expProgressBar: Node | null = null;
// 访问时：
(this.expProgressBar as any).progress = 0.5;
```

### Q8: protoc 编译报 `protoc-gen-go: program not found`

**原因：** `protoc-gen-go` 不在系统 PATH 中  
**解决：**
```bash
# Windows: 将 GOPATH\bin 加入 PATH
$env:PATH += ";E:\GoPath\bin"
# 或永久添加：系统环境变量 → PATH → 添加 E:\GoPath\bin
```

### Q9: MySQL 连接被拒绝

**原因：** MySQL 服务未启动或密码不匹配  
**解决：**
1. 确认 MySQL 正在运行：`Test-NetConnection -ComputerName 127.0.0.1 -Port 3306`
2. 确认配置文件中 DSN 密码与本地 MySQL root 密码一致

### Q10: 端口被占用

**原因：** 8005/8006 端口被其他进程占用  
**解决：**
```bash
# Windows 查看占用
netstat -ano | findstr ":8005"
netstat -ano | findstr ":8006"
# 杀掉对应进程或修改 configs/*.yaml 中的 port
```
