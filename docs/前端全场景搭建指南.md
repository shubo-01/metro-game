### 0.4 通用搭建规范（全文档适用）

1. **节点命名必须与文档一致**：脚本中部分逻辑按名称查找子节点（如 `LoginPanel` 查找 `CloseBtn`）。
2. **Label 统一设置**：字体留空（系统字体）、`CacheMode = NONE`、颜色可先默认（多数脚本运行时会覆盖颜色/文字）。
3. **按钮 = Node + Sprite(底) + Label(字)**：所有按钮事件均由脚本 `onLoad` 中 `node.on(TOUCH_END)` 代码绑定，**不需要在 Inspector 配置 Button ClickEvents**。给按钮节点加 `Button` 组件仅为了按压变色反馈（可选）。跨面板动作（如"加点"按钮打开加点面板）统一走 `EventManager` 事件总线，禁止面板间直接互相调用。
4. **面板初始隐藏**：弹窗类面板（BindPhonePanel、CreatingPanel、第四~七章各 ui/ 面板）创建后在 Inspector 取消勾选节点 active，或由脚本控制。**例外：第九章的三个 V2 面板必须保持勾选 active**，原因见第九章的 ⚠️注意。
5. **Toast 标签**：每个面板都有 `toastLabel`，初始 active=false，脚本会自动显示/隐藏。
6. **设计分辨率**：项目 4 个场景的 Canvas 均为 **1280×720**（Fit Width + Fit Height 同时勾选）。新建场景时保持与之一致。


### 1.2 搭建步骤

1. 资源管理器 `assets/scenes` 右键 → 新建 → Scene，命名 `Login`（若已存在跳过）。
2. 选中 `Canvas` → Inspector → 添加组件 → 自定义脚本 → `LoginPanel`。
3. 按 1.1 节点树逐个创建子节点：
   - 右键 Canvas → 创建 → 2D 对象 → Sprite（Background/按钮底）。
   - 右键 Canvas → 创建 → 2D 对象 → Label（各文本）。
   - 右键 Canvas → 创建 → UI 组件 → EditBox（PhoneInput/CodeInput）。
4. 推荐布局（1280×720 画布，坐标为节点 Position）：
   - TitleLabel (0, 180)，SloganLabel (0, 110)
   - WxLoginBtn (0, -40) 尺寸 320×72，PhoneLoginBtn (0, -140) 尺寸 320×72
   - ServerStatusLabel (0, -240)，VersionLabel (0, -290)
   - BindPhonePanel 居中 (0,0) 尺寸 520×360；内部 PhoneInput (0,80)、CodeInput (0,10)、SendCodeBtn (170,10)、CloseBtn (235,155)
   - ToastLabel (0, 250)

## 第九章 人物属性 V2 三大新面板（加点/洗点/异常状态）

> 状态：**三个脚本均已存在（`scripts/ui/`），需在 Hall.scene 新建节点。**
> 脚本：`AttributeAllocationUI.ts`（加点面板）、`WashPointUI.ts`（洗点确认框）、`AbnormalStatusUI.ts`（异常状态栏）。
> 打开方式：全部由 `EventManager` 事件驱动，**没有任何按钮直接引用这三个面板**：
> - 加点面板 ← 监听 `CharacterV2Event.OPEN_ALLOCATE`（角色面板"加点"按钮触发）
> - 洗点确认框 ← 监听 `CharacterV2Event.OPEN_WASH`（角色面板"洗点"按钮触发）
> - 异常状态栏 ← 监听 `CharacterV2Event.ABNORMAL_TRIGGERED`（战斗逻辑广播判定结果）

> ⚠️注意（三个面板通用，最容易踩的坑）：这三个面板节点在场景中**必须保持初始激活（Inspector 勾选 active）**，与第四~七章"弹窗初始取消勾选"的惯例相反！
> 原因：事件监听注册写在组件 `onLoad()` 里，而 Cocos Creator 中**未激活节点的组件不会执行 onLoad**。若初始取消勾选，事件永远收不到，面板永远打不开。
> 正确做法：保持勾选 → 加点面板/洗点确认框的 `onLoad()` 注册完事件后会自行执行 `this.node.active = false` 隐藏；异常状态栏则常驻显示（内部三个图标自行隐藏）。

### 10.2 CharacterV2Event 事件总线（面板间通信全靠它）

项目规范：按钮触发的跨面板动作一律走 `EventManager`，禁止面板间直接 onClick 回调。事件常量定义在 `CharacterApi.ts` 的 `CharacterV2Event` 枚举中：

| 事件常量 | 事件名字符串 | 谁 emit（触发时机） | 谁监听（做什么） |
|---|---|---|---|
| `OPEN_ALLOCATE` | `charv2:open_allocate` | CharacterPanel"加点"按钮点击（可携带 unassigned_points 参数） | AttributeAllocationUI → 打开加点面板并拉取当前属性 |
| `OPEN_WASH` | `charv2:open_wash` | CharacterPanel"洗点"按钮点击 | WashPointUI → 打开洗点确认框 |
| `ATTR_UPDATED` | `charv2:attr_updated` | 加点成功 / 洗点成功 / 神魔子阶突破成功（携带最新接口响应数据） | CharacterPanel → 重新拉取全部数据刷新 |
| `POINTS_UPDATED` | `charv2:points_updated` | 升阶发点（RealmBreakthroughUI）/ 加点扣点 / 洗点返还成功（参数：unassigned_points 数值） | AttributeAllocationUI → 更新"剩余可分配"余额 |
| `DAO_UPDATED` | `charv2:dao_updated` | CharacterApi 封装层：`daoGain` 请求成功（code=0 且有 data）后自动广播（携带 DaoGainData，含全部 5 种道值） | RealmBreakthroughUI → 缓存道值并刷新道进度 |
| `ABNORMAL_TRIGGERED` | `charv2:abnormal_triggered` | CharacterApi 封装层：`combatAbnormal` 请求成功后自动广播（携带 CombatAbnormalData） | AbnormalStatusUI → `triggered=true` 时亮图标并倒计时 |

事件数据流转示意（新手理解用）：

```
[境界面板] 升阶成功(响应带unassigned_points) ──POINTS_UPDATED──▶ [加点面板] 余额更新
[角色面板] 点"加点" ──OPEN_ALLOCATE──▶ [加点面板] 弹出
[加点面板] 确认加点成功 ──ATTR_UPDATED──▶ [角色面板] 刷新
                      └─POINTS_UPDATED──▶ [加点面板自身] 余额更新
[角色面板] 点"洗点" ──OPEN_WASH──▶ [洗点确认框] 弹出
[洗点确认框] 确认洗点成功 ──ATTR_UPDATED + POINTS_UPDATED──▶ 同上
[战斗逻辑] daoGain成功 ──DAO_UPDATED──▶ [境界面板] 道进度刷新
[战斗逻辑] combatAbnormal触发 ──ABNORMAL_TRIGGERED──▶ [异常状态栏] 图标+倒计时
```

### 13.1 业务背景速览（读懂了再搭，文案都由脚本自动填充）

- **12 个神位**，三个维度描述：品级（凡/珍/灵/仙/神话/先天 6 级）、属性系（妖属加精 / 魔属加气 / 道属加神）、阶位（兵/将/帅，仅融合线神位有）。
- **碎片合成**：7 个同名碎片 → 1 个完整神位（碎片列表显示 `x/7` 进度）。
- **融合升阶**：9 个同品级同属性系完整神位 → 1 个高一阶神位（兵→将→帅，帅为当前最高阶）。
- **继承**：消耗 1 个完整神位，永久解锁并立即激活。门槛 = **裸体精气神总和**（不含神位加成）≥ `base + perLevel×(Lv-1)`：凡品无门槛，珍 200+3(Lv-1)、灵 500+7(Lv-1)、仙 1200+15(Lv-1)、神话 3000+30(Lv-1)、先天 7000+50(Lv-1)。Lv = (minor_stage-1)×10 + stage_segment + 1。
- **切换**：在"已继承"神位之间切换激活。目标在当前神位上位链上（如美猴王→齐天大圣）为**晋升，免费**；普通切换按**旧（当前激活）神位品级**扣灵石+归元符：凡 10+1符 / 珍 30+2 / 灵 80+2 / 仙 150+3 / 神话 300+4 / 先天 500+5（归元符单价 99 灵石，总当量 109/228/278/447/696/995）。
- 业务错误码（脚本已内置中文兜底文案，无需前端处理）：4001 碎片不足 / 4002 融合材料不足 / 4003 已最高阶 / 4010 门槛不足 / 4012 需先继承下属 / 4020 灵石不足 / 4021 归元符不足。

### 16.1 业务背景速览（读懂了再搭，文案都由脚本自动填充）

- **摇杆**：`maxRadius`（默认 80px）内拖动输出归一化方向 + 8 方向档位 octant（0右 1右上 2上 3左上 4左 5左下 6下 7右下）；死区 `deadZone`（默认 10px）内不输出。广播 `JOYSTICK_MOVE`/`JOYSTICK_END`，HallScene 收到后按服务端 `move_rule.base_speed`（5 米/秒）× `MapConfig.PIXELS_PER_METER` 换算像素速度移动——**摇杆优先级高于点击寻路**。多点触控防抖：脚本记录首个触点的 `touchId`，只接受同一触点的 MOVE/END/CANCEL，第二根手指划过摇杆区不会干扰方向。

### 19.1 PanelManager（纯静态类，无需挂载任何节点）

`scripts/manager/PanelManager.ts` 不是组件，**不要往任何节点上挂**，直接 `import` 静态调用。

- **面板类型枚举** `PanelType`（5 个）：`Inventory='inventory'`、`Shop='shop'`、`Settings='settings'`、`ItemDetail='item_detail'`、`ShopConfirm='shop_confirm'`。前三个是一级面板，后两个是二级子面板。
- **注册机制**：每个面板在自己的 `onLoad` 里调 `PanelManager.register(type, { show, hide, maskNode })` 把"怎么显示/怎么隐藏"交给管理器，在 `onDestroy` 里调 `unregister(type)` 防止场景切换后悬空引用。**未注册的面板调 openPanel 会被静默忽略**——这就是"面板脚本没挂/节点没激活时点入口没反应"的根因。
- **一级面板互斥**：`openPanel(A)` 会先 `closeAll()` 关掉正在开着的一级面板 B（含其二级子面板），保证同时只显示 1 个一级面板；已经开着的面板重复调不会重复 show。
- **最多两级**：`openSubPanel(type)` 要求栈里已有一级面板；已有二级时先关旧二级再开新的。
- **关闭**：`closeTop()` 只关栈顶（二级开着时只关二级、回到一级），`closeAll()` 从栈顶往下全关。所有面板的关闭按钮/取消按钮统一调 `closeTop()`。
- **战斗例外**：`setCombatMode(true)` 后 `openPanel` 不再自动关旧面板（PRD 7.1 例外条款，避免打断战斗操作）。**实际调用点在 CombatHUDUI**：`setTarget(defenderId)` 时按 `defenderId > 0` 进战/`= 0` 脱战切换战斗模式，`onDestroy` 兜底置回 false 防状态泄漏——新接入方必须成对调用 true/false。
- **查询**：`isOpen(type)` / `topPanel()` / `hasAnyOpen()`（TutorialUI 引导层避让用）。
- **广播**：打开/关闭时发 `UIEvent.PANEL_OPENED` / `PANEL_CLOSED`，携带 `{type, level}`（level=1 一级、2 二级）。消费者是 **TutorialSystem**（引导第 3 步判定）与 **TutorialUI**（一级面板打开时隐藏引导层）。
- **范围**：仅 V6 新四面板（背包/商店/设置/物品详情/数量确认）走本管理器，第四~十五章的既有面板**不迁移**（避免回归），它们的层级仍按第八章的手动规则处理。

### 19.2 SettingsStorage（纯静态类，无需挂载任何节点）

`scripts/manager/SettingsStorage.ts` 同样不是组件。它是 17 项设置的**唯一读写入口**，其他系统一律通过它取值，不要各自读 storage。

- **存储键** `xunxian_ui_settings`；微信小游戏走 `wx.getStorageSync/setStorageSync`，浏览器走 `localStorage`，双端自动判断。
- **本地优先**：`getAll()` 首次调用从本地加载并用 `Constants.SettingsDefaults`（17 项默认值，与后端 DDL 逐项一致）兜底缺字段，未登录/断网也能用。
- **登录后同步**：`HallScene.onLoad` 调 `SettingsStorage.syncFromServer(characterId)` 拉服务端设置覆盖本地；服务端返回 `is_default=true`（还没存过）时反向把本地值推上去。
- **修改即存**：`set(key, value)` 立即写内存+本地，再异步 POST 落库（失败静默，本地已生效；未登录 `characterId=0` 时跳过请求）。
- **重置**：`reset()` 本地立刻恢复默认 + 调服务端 reset。注意 **`tutorial_skipped` 后端只升不降**，重置后仍可能是 1。
- **6 个语义读取点**：`isScreenShakeOn()`（FloatingDamageText 暴击震动）、`isDamageNumbersOn()`（伤害数字总开关）、`getJoystickSensitivity()`（摇杆灵敏度，JoystickUI 预留）、`getBgmVolume()` / `getSkillVolume()` / `getEnvVolume()`。
- ⚠️ **音量项目前只存值不生效**：工程内暂无 MusicManager，三条音量滑条改了会正确落库/回显，但听不到变化，接入点已预留。

### 20.1 业务背景速览

- **背包 30 格是 UI 固定值**（6 列 × 5 行，PRD 3.1），而**实际可用容量以接口 `capacity.total_slots` 为准**（基础 20 格 + 腰带扩展）：前 N 格放物品，超出 `total_slots` 的格子画锁定态🔒（灰色），中间的空格为空白。顶部显示「容量 已用/总数」与「灵石 N」。
- **分类 Tab 5 个**：0 全部 / 1 药品 / 2 材料 / 3 武器 / 4 护符——**背包的 `item_type` 与商店的 `category` 同一套取值**。点 Tab 重拉接口（不是本地过滤）。
- **物品详情（二级）**：点有物品的格子才开（空格/锁定格无反应）。「使用」按钮只在 `usable=true` 时显示、「出售」只在 `sellable=true` 时显示（脚本自动控制 active）。使用成功按 `effect_type` 弹不同文案（1 回血带 heal 与当前/上限，2 挪移符为纯前端演出）；`6413` 冷却中时按响应的 `cd_remaining` 提示剩余秒数。背包内出售固定**一次卖 1 个**（批量出售走商店面板的数量确认弹窗）。
- **商店**：每行显示「名称（分类） 价格 N 灵石 回收 M 灵石」，**回收价 = 购买价 50%**（PRD 8.3，后端算好下发）；商品清单 PRD 8.1（凡品药 3 灵石 / 挪移符 49 灵石 / 铁 1 灵石）。
- **数量确认（二级）**：点行内「购买」/「出售」开弹窗，+/- 调数量，**下限 1、上限 999**（与后端 `count>999` 返回 400 同口径）；买时显示「合计 N 灵石（余额 M）」并**前端预检灵石**（不够直接 toast，权威判定仍在后端 6421），卖时显示「可得 N 灵石」。
- **买/卖后一律重拉列表**：余额与商品状态以服务端为准。`SHOP_SOLD` 事件**两个面板都监听**（各自先判断自己的 panelRoot 是否开着再刷）。

### 21.2 颜色映射表与字号公式

**字号公式**（技术文档 2.4 伪码）：

```
字号 = 12 × (1 + 伤害 / 目标最大HP × 2)   ← 基础 12pt
暴击时再 × 1.5（叠乘）                        ← damage_type=1
最终限幅上限 48pt（防超大伤害把字撑爆，假设值可配）
目标最大HP ≤ 0 或 伤害 ≤ 0 时按基础字号 12pt
```
例：打掉14% 血量的普攻 → 12×(1+0.14×2) ≈ 15pt；同样伤害的暴击 → 再×1.5 ≈ 23pt；一击打掉50% 血的暴击 → 12×2×1.5 = 36pt。

**演出参数**：上浮 **30 px** / 时长 **0.5 秒**同步渐隐（文档值）；对象池 **16** 条；同目标多数字**横向交错堆叠**（步长 18px，0 → +18 → -18 → +36 → -36 交替排开，假设值可配）。

### 21.5 TutorialSystem 4 步流程与引导目标注册

`scripts/manager/TutorialSystem.ts` 是**纯静态类，无需挂载**；`HallScene.onLoad` 已调 `TutorialSystem.init(characterId)` 拉状态并绑定全部完成条件事件，`onDestroy` 调 `shutdown()`。**已完成/已跳过的老角色 `next_step=0`，状态机不启动**（想重测请新建角色）。

| 步 | 后端完成条件 | 前端实际判定触发点 | 高亮/箭头目标 |
|---|---|---|---|
| 1 | `talk` / `npc_elder` | 监听 `NPC_TALKED`（HallScene NPC 对话后广播）；工程 NPC 表无"营地长者"，**用张真人（npcId=1）代任**（假设值可配） | `npc_elder` → HallScene 已注册 |
| 2 | `reach` / `npc_blacksmith` | 监听 `MapEvent.PLAYER_POS_CHANGED`（0.5 秒节流的米坐标），离**铸器师 (780, 300) 米 ≤ 5 米**即到达（沿用采集半径口径） | 高亮 `joystick` → JoystickUI 已注册（摇杆脉冲）；箭头 `npc_blacksmith` → **未注册**，箭头隐藏只显文案 |
| 3 | `equip` / `weapon` | 工程暂无"装备成功"事件，**兜底口径：监听 `UIEvent.PANEL_OPENED(type=inventory)`——打开背包即视为完成**（假设值可配） | `btn_inventory` → HallUI 已注册 |
| 4 | `reach` / `camp_exit` | 监听 `MapEvent.ZONE_ENTERED`，进入非营地分区（`zone_id ≠ 1`）即视为走出营地 | `camp_exit` → HallScene 已注册（分区数据到达后在**营地东边界中点**动态创建 `CampExitMarker` 标记节点；分区拉取失败时不创建，自动降级只显文案） |

- **注册机制**：高亮/箭头目标按元素 ID 查表，由各自持有者调 `TutorialUI.registerTarget(id, node)` 注入（HallScene 注 `npc_elder` 与 `camp_exit`、HallUI 注 `btn_inventory`、JoystickUI 注 `joystick`），`onDestroy` 调 `unregisterTarget` 清理。**未注册的目标不报错**：箭头自动隐藏、不做脉冲，只显文案，引导仍能正常推进。
- **推进与奖励**：每步完成调 `/character/tutorial/advance` 上报（防重入），**顺序权威在后端**：6402/6403 业务错误的中文文案经 `TUTORIAL_TOAST` 事件由 TutorialUI 用 toast 弹 2 秒反馈给玩家；其中**仅 6403（已结束）本地停机自愈**，6402（非法跳步）只提示不停机、等 status 重拉纠正（不自动重拉防循环）；第 4 步完成后端事务发奖（PRD 4.4：灵石×1 + 凡品武器×1 + 凡品药×3），TutorialUI 用 toast 展示「引导完成！获得：灵石×1、…」。
- **跳过**：`skipBtn` → 二次确认 → `TutorialSystem.skip()` → `/character/tutorial/skip`。**不可逆、不发奖励**，且 `tutorial_skipped` 后端只升不降（设置面板只读展示为「已跳过（不可恢复）」）。
- **面板避让**：收到 `PANEL_OPENED(level=1)` 时 GuideRoot 隐藏，`PANEL_CLOSED(level=1)` 且引导还在跑时恢复——所以第 3 步点开背包后箭头会消失，属**正常设计**。
